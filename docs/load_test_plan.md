# 压测计划与报告模板

**尚未执行真实双4090/200人压力测试。** backend与部署TEST_REPORT是功能/静态验证，不含真实吞吐、P95或显存成绩。[报告模板](examples/load_test_report.json)所有实测数值为null；不得用演示时间或计划目标填成已测结果。

## 环境冻结

记录commit（当前无Git提交则记录归档SHA256）、模型精确revision、CPU/RAM、两卡ID/驱动/PCIe拓扑、Docker/vLLM版本、全部有效参数、数据库/Redis是否真实实例、是否开启reranker、知识块数量、输入输出token分布。demo与真实模型必须分别报告。

使用独立测试身份与合成库，不引用真实学生对话。当前production拒绝合成导入器，需在隔离测试环境采用demo=true并显式配置真实BGE/vLLM，或另写授权真实导入器；mode可能是vllm，demo开关仍影响启动数据，必须记录。

## 场景

| 场景 | 检查内容 |
|---|---|
| 单意图教室 | 正确日期、available过滤 |
| 教室+菜品 | 两工具结果、偏好/预算 |
| 缺日期后补日期 | 同会话槽位、没有编造日期 |
| RAG公共/私有 | 来源、召回、越权返回数=0 |
| 长历史与长技能 | token总量、上下文超限与延迟 |
| Redis断开/缓存满 | SQL回退与错误分布 |
| 工具/模型慢或不可达 | 超时、错误码、恢复 |
| 同会话同时请求 | 顺序、版本冲突、无丢失 |
| ASR/TTS | 上游真正部署后单独测，不能计入尚未运行的能力 |

建议冷启动先测1次完整加载；预热后从1、2、4、8、16并发逐级，每级稳态至少5分钟、重复3次。并发客户端数不是到达率，应另做受控到达率测试（如5/10/20请求每分钟）观察队列。所有级别需相同输入分布，超时也计入统计，不只统计成功快请求。

当前无Locust/k6压测脚本，计划可用上述工具落地，但不能运行空load_tests骨架后称已完成。每个chat请求可能多次LLM调用，必须同时统计API请求与推理请求，二者不要混淆。

## 指标与建议验收目标

| 指标 | 如何获取 | 状态/目标 |
|---|---|---|
| 成功率/错误率 | 全部HTTP状态与异常次数 | 建议>=99%，尚未验收 |
| E2E P50/P95/P99 | 客户端完整响应墙钟耗时 | 目标由交互要求确定，当前未实测 |
| 完成吞吐 | 稳态成功chat数/秒 | 与到达率一起报告 |
| TTFT/每输出token耗时 | vLLM流式探针或监控 | 当前chat非流式，不能从chat直接读TTFT |
| 输入/输出tokens | 模型统计或探针 | 当前ModelClient不把usage持久化 |
| 队列/active sequences | vLLM指标（部署后核对版本） | 区分API在途与模型active |
| 每卡峰值显存 | nvidia-smi定期采样 | 两卡分别报告，须记录采样间隔 |
| SQL/Redis/RAG耗时 | 分段监控或日志埋点 | 目前未实现完整分段指标 |
| 工具参数/结果正确率 | 固定问题与标准行核对 | 与HTTP成功率分开 |
| 越权数据返回 | 私有资料和消息归属用例 | 必须0 |

## 根据报告调整（条件方案，非已经发生）

| 观察 | 调整候选 | 复测内容 |
|---|---|---|
| OOM | 降上下文/active序列；确认AWQ与占用进程 | 显存、正确性、长任务是否仍覆盖 |
| 长prefill拖慢短请求 | 复核chunked prefill与batch token | 相同长短比例的P95/吞吐 |
| 排队持续增长 | 减工具轮次/提示长度，增加入口限流需开发 | 到达率、等待、超时比例 |
| RAG未命中专有词 | 调整分词/候选/重排 | Recall@k、权限和延迟 |
| Redis占用过高 | 缩小快照/分页需开发 | 3天TTL保留、SQL压力、缓存字节 |
| 业务查询过慢 | 规范化查询字段/索引需迁移 | SQL扫描量与正确结果 |

学院要求的3天TTL已作为默认配置，是场景设定；没有证据表明它是从已完成的压测推导出来。报告应保留每次调整的before/after、同一测试集与副作用，不填造“提升30%”。
