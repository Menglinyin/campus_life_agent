# 空闲教室查询流程

## 目标和前置条件
依据查询结果提供自习地点。先确认日期：今天、明天、后天按 Asia/Shanghai 解释；绝对日期使用 YYYY-MM-DD。用户本轮明确日期优先于历史日期。未确认日期时询问“你想查询哪一天？”，不猜测日期或空闲状态。

## 执行
1. 使用 `query_classrooms`，参数只有已确认的 `date`。不要传 user_id、building、start_time、end_time、min_seats 等未实现参数。
2. 最小调用示例：`{"name":"query_classrooms","arguments":{"date":"2026-10-04"}}`。该日期仅演示格式，实际调用取本次确认日期。
3. 根据返回的 `rows` 展示 name、date、seats，只展示 available=true 的记录。数据可能来自演示数据集，不能称作实时教务系统数据。
4. 用户问“下午两点到四点是否空闲”时，说明当前工具只提供日期级 available 标记，没有时段占用信息，不能由该标记推断全天或具体时段空闲。不要伪造分时查询。
5. 无结果时说明该日期没有查到可用记录，允许用户换日期。超时或异常说明查询未完成；不得把工具错误解释成“没有空闲教室”。

## 回复和权限
回复以工具记录为依据，不生成不存在的地点、开放时间或座位数。若用户同时查询课程或菜品，分别遵循对应技能，沿用明确日期并分项呈现。开放制度或预约须知通过 `search_knowledge` 查询，并保留来源；没有学校正式资料时说明无法确认。
本技能不预约教室、不修改课程占用、不访问其他学生会话。用户身份由后端认证和 MCP 请求上下文提供，不从文本、技能或工具结果获得。
