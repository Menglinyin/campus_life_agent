# 饮食字段与偏好

| 参数 | 范围与含义 | 注意事项 |
| --- | --- | --- |
| budget | 0..1000，单份菜品价格上限 | 0 是有效输入，不等于未设置 |
| spice | 整数 0..2，最大允许辣度 | spice=1 同时允许不辣和微辣 |
| vegetarian | true / false | false 不排除素食，仅移除素食限制 |
| date | 确认的查询日期 | 必填业务条件，缺失先询问 |

Agent 的偏好抽取器是现有规则实现，并非任意自然语言都能识别。接入模型时仍需后端 schema 检查；技能提示不构成参数校验。
评分降序、价格升序的排序和最多10条限制由 recommendations 服务执行。重复记录、错误标签和失效菜单需要从数据源修正，修改技能不能修复它们。
当前没有过敏原、配料、热量、清真认证、库存数量等字段。不要把 vegetarian 标签扩大解释为这些性质。
用户最新明确偏好优先于缓存偏好。偏好存储由后端处理；Redis 会话 TTL 为259200秒（3天），不等于 MySQL 历史或长期记忆的保留期。
